API Documentation

Free, open API for password analysis and breach statistics

Base URL

https://muddy-scene-9bdf.haveubeenpwned.workers.dev

All API endpoints are free to use with no authentication required. Rate limits apply (100,000 requests/day).

Endpoints

POST /check

Submit a password and get HTML awareness page back (like using the website, but via API)

Request Body:

Parameter Type Required Description
password string Yes The password to analyze

Example Request:

curl -X POST https://muddy-scene-9bdf.haveubeenpwned.workers.dev/check \ -H "Content-Type: application/json" \ -d '{"password": "MyP@ssw0rd123"}' \ -o result.html && open result.html

Response:

Returns HTML page with password analysis, security rating, and tips

Privacy Note:
Password is analyzed immediately and NOT stored. Only anonymized metadata (length, complexity) is saved for research statistics - just like using the website.

POST /analyze

Analyze password metadata (for programmatic use) - returns JSON

Request Body:

Parameter Type Required Description
length integer Yes Password length
has_number boolean Yes Contains numbers (0-9)
has_special boolean Yes Contains special characters

Example Request:

curl -X POST https://muddy-scene-9bdf.haveubeenpwned.workers.dev/analyze \ -H "Content-Type: application/json" \ -d '{"length": 12, "has_number": true, "has_special": true}'

Response:

{"status": "ok"}

GET /stats

Get aggregated password statistics - returns JSON

Example Request:

curl https://muddy-scene-9bdf.haveubeenpwned.workers.dev/stats

Response:

{ "total": 42, "length_0-7": 5, "length_8-12": 25, "length_13+": 12, "complexity_low": 8, "complexity_medium": 20, "complexity_high": 14, "number_true": 35, "number_false": 7, "special_true": 28, "special_false": 14, "time_morning": 15, "time_afternoon": 18, "time_evening": 9 }

Bash Script Examples

Option 1: Get HTML Result (Recommended)

Submit password and get HTML awareness page back:

#!/bin/bash PASSWORD="MyP@ssw0rd123" curl -X POST https://muddy-scene-9bdf.haveubeenpwned.workers.dev/check \ -H "Content-Type: application/json" \ -d "{\"password\": \"$PASSWORD\"}" \ -o result.html echo "Results saved to result.html" open result.html # macOS # xdg-open result.html # Linux # start result.html # Windows

Option 2: Send Only Metadata (Maximum Privacy)

Analyze locally and send only anonymized metadata:

#!/bin/bash PASSWORD="MyP@ssw0rd123" # Analyze locally LENGTH=${#PASSWORD} HAS_NUMBER=$(echo "$PASSWORD" | grep -q '[0-9]' && echo "true" || echo "false") HAS_SPECIAL=$(echo "$PASSWORD" | grep -q '[^A-Za-z0-9]' && echo "true" || echo "false") # Send only metadata curl -X POST https://muddy-scene-9bdf.haveubeenpwned.workers.dev/analyze \ -H "Content-Type: application/json" \ -d "{\"length\": $LENGTH, \"has_number\": $HAS_NUMBER, \"has_special\": $HAS_SPECIAL}"

Privacy & Data Collection

  • The /check endpoint: Receives password, analyzes it, and returns results. Password is NOT stored, only analyzed in-memory.
  • The /analyze endpoint: Receives only anonymized metadata (length, has_number, has_special) - maximum privacy
  • Both endpoints contribute to Research statistics with anonymized data (length buckets, complexity, time of day)
  • Data cannot be linked back to individual users or passwords
  • All submitted data becomes part of public research statistics
  • Choose the approach that matches your privacy needs
